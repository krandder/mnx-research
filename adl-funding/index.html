Funding-stall solvency invariants

Companion to the ADL replacement-capacity invariants. That note bounds the oracle-price shock channel. This note bounds the second shock channel the M01B funding-shortfall run exposed: atomic funding realization after an index stall.

Short Version

Funding accrues in chain time but is realized only when updateGlobalIndex() mines. The contract applies rate × timeDelta with unbounded timeDelta, so a stalled updater realizes the whole backlog as one atomic equity shock. If that shock pushes an account past zero equity, the floor write-off mints an unbacked claim (forgiven), the market pool goes short by exactly that amount, and the ADL of the account reverts with Insufficient account funds.

Buffer requirement, funding as a second bounded shock
liquidation buffer >= max(J, F)
F is bounded by the existing on-chain rate cap and an ops SLO
F = rate_cap × stall   ⇒   F <= J  iff  stall <= T_max = J / rate_cap

What this buys

No smart-contract changes. The rate cap already exists on-chain (FundingOracle.maxFunding); everything else is an off-chain guarantee the runtime can enforce, because every equity-moving action is already exchange-relayed and forced backlog realization is already oracle-gated on-chain.

The Failure Mechanism (Observed, Not Hypothetical)

Evidence: the M01B funding-shortfall replay (run m01b-local-time-oracle-20260630-001) — a 13-day Anvil time warp against a real API-opened position on a disposable local-chain stack.

1. Unbounded realization

_computeFundingIndex applies rate × timeDelta × price from block timestamps (Perpetual.sol:2484–2495). A wall-clock cadence (1s updater job) cannot bound the chain-time delta across a stall or warp.

2. Write-off asymmetry

At settlement (_settlePendingFunding, Perpetual.sol:2277–2326) the credit side books the full funding claim; the debit side is floored at margin + positive PnL and the remainder is forgiven. Claims now exceed the pool by exactly forgiven, atomically with the settlement.

3. ADL cannot settle

ADL pays the counterparty from the perpetual’s pooled bank account (_transferMargin, Perpetual.sol:1855). Short pool → Insufficient account funds revert in a thin market, or a silently socialized hole in a thick one.

The structural point

No liquidation ordering can prevent this: pre-jump the account is healthy, post-jump the hole already exists. Only bounding the per-realization funding delta — or neutralizing the backlog before realization — preserves solvency.

Definitions

F

The maximum funding shock a single index realization can apply, as a fraction of notional: rate_cap × stall_duration.

rate_cap

The on-chain funding-rate bound, FundingOracle.maxFunding, applied per second in setFundingRate. Already enforced; not a new mechanism.

T_max

The longest index stall for which F <= J still holds: T_max = J / rate_cap. Beyond it, the freeze protocol below takes over instead of the buffer.

The Invariant And Why max(J, F) Is Sound

max(J, F) rather than J + F assumes update events are serialized against sweeps: after any accepted update event (oracle jump or funding realization), the liquidation/ADL sweep completes before the next event of either type. All serialization points are exchange-controlled:

Chokepoint Gate Where
Forced backlog realization by third parties Blocked on-chain: updateGlobalIndex requires a fresh oracle vs block time (P48) Perpetual.sol:2385
Trades Settlement-operator only; runtime already halts batch sealing on stale price runtime-oracle-freshness.ts
Position-margin withdrawal Settlement-operator only (removeMargin / removeMarginUpTo); Guardian whenTradingAllowed as hard switch Perpetual.sol:939, 977
Oracle price pushes Exchange-run relayer; J-capped per accepted update runtime

The off-chain guarantee, stated once: oracle price updates and funding-index updates advance only together with completed sweeps, or not at all.

Freeze Protocol For Stalls Beyond T_max

If index staleness exceeds threshold, the runtime withholds oracle price updates too. That freezes the market’s equity state and — via the same P48 gate — makes backlog realization impossible for everyone until recovery. Recovery is ordered so zero funding realizes:

1

Guardian suspends funding via setFundingRateStatus — this zeroes currentFundingRate (FundingOracle.sol:343) and needs no fresh oracle.

2

Push a fresh oracle price. If spot moved during the freeze, this happens in J-capped steps with a completed sweep between each step — the replacement-capacity machinery doing its job on the accumulated price move.

3

updateGlobalIndex catches up. Realization is 0 × timeDelta × price = 0: the index timestamp syncs, no funding realizes, no write-off can mint. Front-running this call gains nothing — the rate is already zero.

4

Sweeps clear anyone the price steps made liquidatable, at positive equity, into book liquidation or backstop inheritance.

5

Guardian re-allows funding; the rate restarts from zero (FundingOracle.sol:354). Trading resumes.

Economic decision to ratify

This forfeits stall-period funding for both sides. Position: funding exists to converge perp to spot during trading; a frozen market has no premium to pay for. Needs sign-off and should be documented for the auditors as intended behavior.

What To Build (All Off-Chain)

1. Staleness protective mode

Mirror the oracle-price freshness gate for the funding index: alert at minutes, halt batch sealing and enter the freeze at ~1 hour, page long before T_max. Sweeps stay enabled.

2. Sweep-after-update discipline

Wire the dormant requestLiquidationCheck coupling so every accepted update triggers an immediate sweep, and gate the runtime’s own updateGlobalIndex submissions on sweep completion.

3. Projected-equity withdrawal gate

During staleness, the runtime extrapolates rate × elapsed off-chain and refuses to relay margin removals that projected equity cannot support (or relays none during a freeze).

4. Relayer redundancy

Redundant submission paths for the index updater and price relayer so hour-scale stalls are rare events.

5. mnx-status monitoring

Per-market global-index staleness (headline metric), oracle relayer staleness, consecutive refresh failures, sweep lag, funding-settlement-keeper health, Guardian funding status.

6. M01B as regression

The 13-day-warp run becomes the beyond-T_max regression test: assert freeze engages, recovery runbook realizes zero funding, and no write-off mints.

Residual Risks This Does Not Remove

Same-block adjacency

An oracle update and an index realization can land in one block with no sweep between: residual write-off up to typical-F (~0.0002% at 5s cadence). Dust-level; absorbed by the backstop layer.

Bugs and misconfiguration

The guarantee is operational, not cryptographic. ADL should still not assume a solvent pool; the forgiven-repair path (backstop top-up) remains as defense-in-depth.

Free-collateral exit

requestWithdrawFromBank is permissionless but touches only unlocked bank balance (delayed), not position margin. Not a solvency threat; noted for completeness.
