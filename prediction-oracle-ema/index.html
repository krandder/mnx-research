The guard is a clamp, not an average

L = max(0, B − 0.10)   U = min(1, A + 0.10)   O = clamp(EMA8h, L, U)
B = 1,000-share depth-weighted YES bid A = 1,000-share depth-weighted YES ask O = oracle target before the existing on-chain step bound
No blending

Inside means untouched

The external price receives no weight. If the internal EMA is in the permitted interval, it is the target exactly.

Absolute gap

Ten probability points

g = 0.10 is an absolute probability distance, not 10% of the current price.

Payout domain

Always within [0, 1]

The lower and upper edges are capped at the binary payout boundaries before the clamp.

Which markets are officially connected?

MNX market Polymarket guard Reason Oracle behavior
DPREZ Yes The reviewed external condition is semantically equivalent to the MNX settlement question. Internal eight-hour EMA, clamped to the external guard interval.
ANTHTOP26 No MNX settles on Epoch’s Capabilities Index; the prior external mapping settles on Chatbot Arena / LMArena. Internal eight-hour EMA only. A stale database row cannot activate a guard.
OAITOP26 No MNX settles on Epoch’s Capabilities Index; the prior external mapping settles on Chatbot Arena / LMArena. Internal eight-hour EMA only. A stale database row cannot activate a guard.
Semantic equivalence is the authorization boundary. Similar wording is insufficient. If settlement sources or criteria differ, the external market is not a valid oracle reference.

Failure policy

DPREZ · reviewed guard required
Publish Exact reviewed token and condition, plus a fresh, valid two-sided book with at least 1,000 YES shares per side.
Freeze Connector missing, disabled, malformed, or different from the reviewed identity.
Freeze External fetch fails, identity differs, either side is thin, the book crosses, or touch/depth spread exceeds 0.05.
AI-top markets · no guard authorized
Publish The futures updater uses the normal internal EMA path without requesting Polymarket data.
Ignore A stale price_connectors row cannot reactivate the deleted mapping.
Delete The rollout migration removes the durable Polymarket rows for ANTHTOP26 and OAITOP26 only.
Disabled is not dormant for a reviewed guard. A non-delisted future with an enabled Polymarket connector continues receiving oracle updates while trading is disabled, so a newly deployed guarded market can converge before the launch gate enables orders. Unrelated connectorless futures remain halted.

Adversarial review results

✓ Writer race removed. The generic connector job now selects perpetuals only; the futures job exclusively owns binary and numeric futures.
✓ Launch deadlock fixed without broadening halts. The first draft filtered out trading-disabled guarded markets; the next draft updated every disabled future. The final query admits only enabled futures plus connector-backed launch candidates.
✓ Deploy ordering is safe. Even before the cleanup migration runs, code ignores stale AI-top mappings; DPREZ fails closed until its exact mapping is available.
✓ Boundary math covered. Tests pin unchanged in-band EMA, ±0.10 clamps, and payout-domain caps at 0 and 1.
✓ Existing controls preserved. The contract’s directional update step and market trading bands remain downstream and unchanged.
Mutation probes deliberately broke the 0.10 gap, exact DPREZ identity, disabled-market convergence, single-writer ownership, AI-top mapping deletion, and migration scope. Each corresponding test failed before the implementation was restored.

  3. Trigger the futures updater and verify EMA/guard provenance plus fresh oracle confirmations.

  1. Remove ANTHTOP26 and OAITOP26 from MARKET_MAKER_POLYMARKET_FAIR_PRICE_ASSETS.
