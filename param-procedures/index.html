MNX Proposal — governance of parameters & fees

How MNX changes parameters: the standing procedure

One published rule set covering every market parameter and fee: which class it belongs to, how much notice a change requires, who signs off, and where it is announced. Extends the already-decided oracle-methodology rule (7-day notice, bug fixes exempt) to the whole parameter surface.

The proposed rules (P1–P4)

#RuleContent
P1 Parameter classes and notice periods Class A — trader-protective or benign (no notice, announced same day): minimum order sizes, spam guards, monitoring thresholds, fee decreases, cap raises (e.g. per-account open-notional tiers), aggregate market-cap adjustments (runtime knob).

Class B — trading economics (7-day public notice): fee increases, tick/step changes, funding caps and strength, leverage/margin requirement changes, oracle methodology (already decided; bug fixes exempt — the exemption applies to every class).

Class C — risk-coupled or structural (published rationale + review window, case by case): take-bound changes (setters are tightening-only; widening requires an Evaluator redeploy), oracle jump caps (tightening-only), contract upgrades, market delistings/settlements (these follow their own decided specs: corporate-actions policy, valuation contract terms).

Emergency powers (immediate, public postmortem within 72h): trading pause, cancel-only mode, funding freeze, the oracle fail-closed hold. Emergencies never loosen a protection — they only pause activity.
P2 Approval Class B and C changes require two-person sign-off (the executing operator plus one of Kelvin / Ian / Stephen), recorded in the announcement. Class A and emergencies: one operator, logged.
P3 Publication docs.mnx.fi carries (a) the canonical per-market parameter tables and the fee schedule, and (b) a changelog page listing every parameter change — date, old → new values, class, reason. The notice clock for Class B starts when the changelog entry is published. Invariant: the docs are the promise; if the docs and the deployed value disagree, that is an incident.
P4 Safety checks Margin, band, and oracle changes run the contract-enforced ADL replacement-capacity invariant before execution (already automatic on-chain); the runbook requires stating the invariant headroom in the change announcement so reviewers see the coupling (band × leverage × oracle speed).

Why classes rather than one blanket rule: a single notice period either blocks urgent protective action or lets economics change under traders' feet. The class split encodes the one principle underneath: changes that can hurt an existing position get notice; changes that protect or loosen constraints don't need it.
