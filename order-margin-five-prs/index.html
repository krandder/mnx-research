Five Small PRs

One idea each, stacked in order. Together they let a market maker quote both sides without paying margin twice, the way Hyperliquid does it, and they end up deleting more code than they add.

The problem in one line. Today every resting order freezes its full margin. A bid and an ask on the same market can never both add to your position, so half of that money is idle. Hyperliquid charges only for what your orders could really do to your position.

1. The rule, written down #1070

One new file, one function, nothing calls it. Given your resting bids and asks, your position and your leverage, it says how much margin those orders need. Orders that add to your position count in full. Orders that would close it are free up to twice its size, because closing and flipping to the same size re-uses the margin you already posted.

2. Track what the rule needs #1074

The rule needs, per account and market, how big your resting bids and asks are and what they are worth. The engine already keeps the sizes. This adds the value at order price next to them, updated the same way and rebuilt after a restart. Nothing reads it yet.

Size +25 linesBehaviour change noneReview passed

3. Show the number, read-only #1075

Each account's balance gains one extra number: what the rule would let it use right now. Cash, minus what is already pending, minus what the rule says the resting orders need in each market. When a market cannot be priced exactly (an order waiting on a trigger, a fill in flight, mixed leverage), that market keeps the old sum, so the number is never too high. Nothing uses it; it only shows up in replies so we can watch it on testnet.

Size +101 / −23 linesBehaviour change noneReview two rounds, passed

4. Let placement use it, switch off #1079

Behind one switch that stays off, placement can accept an order when the extra margin it needs, plus its fee, fits in the number from step 3. Cash is still reserved per order exactly as today. Because of that, the old "available" can go below zero by the amount the rule frees; the checks that would have called that an error now allow it, up to that amount and no further.

Size +123 / −25 linesBehaviour change none while offReview two rounds, passed

5. Throw code away #1083

Earlier PRs (#1001, #1002) had built a second ledger: a cash hold per market, with every change written into the journal. The derived design never reads it, so it goes. Reserved margin is again the plain sum of each order's reservation. Old journals and snapshots still load; the old fields are ignored.

Every PR was attacked by an independent reviewer before it opened, and the whole stack twice more. No way to lose funds was found; everything found above nit level was fixed first.

Not in this stack, on purpose. The one-line PR that turns the switch on. It waits for: the seal-time cash check that cancels only the order that cannot be paid, the read model showing the same effective number (otherwise dashboards show a false shortfall while a quote rests), withdrawals using the new number, a clean shortfall report, and an agreed one-way rollback.
